# 超长回答连续分张截图

用户要求：每张保持当前宽度、字号和较长高度；第一张结束后接着截第二张，依次直到回答末尾。无需 PDF，不重绘回答，不修改视口。

实现版本 capture-pages-v4：

- 小于 8,000 实际像素高的回答维持一次原生截图路径。
- 更长的回答使用整数物理像素坐标规划完整范围，输出每张最高 25,000 像素，并遵守每图 3,200 万像素内存上限。
- 每张内部使用不超过 8,000 像素高的原生截图块。固定同一回答，通过精确位移采集后续区域，不滚动整个会话寻找下一段。
- 在页面脚本暂停保护下逐块拍摄、校验身份和尺寸；所有块拍完后恢复原页面样式、脚本和调试连接，再用 OffscreenCanvas 无损组合原始截图像素。
- 每页保留上下及左右背景留白；拼接不重绘文字或图表，不缩放。页范围要求 startPx 连续且最终 endPx 等于整个回答高度。解码尺寸不符、后续块失败或缺页时不得把前缀声明为完整截图。
- 长图结果通过 screenshotPages 数组传入 worker，每页独立保存为 answer-001.png 等，按截图 1/N、2/N 顺序发出。单张沿用 answer.png。
- screenshotSent 仅在所有页面发送器返回成功后为 true；screenshotPages 提供每页状态，screenshotFiles 提供有序文件列表，screenshotsSent 和 screenshotCount 提供成功数与总数。
- 继续保留旧 screenshot 单张协议，后台 capability 新增 screenshotPages=1。升级后台需在无活动/暂停/投递中任务时重启，扩展重载并刷新后启用新流程。

验证包含 50,000 CSS 像素的实际 Chrome 回答，跨 3 张图片逐像素检查连续性及末尾，在 DPR=1 和 1.25 下均通过。完整回归 96 项通过。模拟了后续截图块失败、页面保存失败、第二张发送失败、全部成功和 silent 仅保存。

资源保护：单次原生拍摄最多等待 10 秒，多块采集最多 90 秒；当前结果上传整体仍受 worker 48 MiB 请求限制。触及限制时应准确报错，不截断后冒充完成。
