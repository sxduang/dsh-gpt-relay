# 回答锚点丢失修复（2026-11-01）

日志确认 2eb4e856、a5592608 在新版投递逻辑中仍报 answer-anchor-lost。上一版仅对节点尺寸变化重拍，节点卸载会直接抛错；临时 DOM 标记也不能跨节点重建保留。

通过现有 probe 读取当前真实 ChatGPT 页面后，确认旧 data-message-id / data-turn-id / article 均不存在。当前消息标识为 data-chatgpt-selection-message-id，外层虚拟对话标识为 data-turn-key。仅按旧属性恢复定位无法处理此页面。

## 修复

- 等待回答和截图恢复均支持当前与旧版稳定消息属性。收集原图之前保存目标身份，避免异步期间节点被换掉后丢失身份。
- 后台在初始定位、布局稳定等待及截图后校验阶段丢失节点时，恢复临时样式，再按同一稳定消息 ID 获取新的可见节点，最多尝试 4 次。
- 恢复还核对正文类型、文字首尾和唯一性，不选隐藏副本，不回退到最后一条或相似文本的其他消息。
- 临时截图前固定回答到原对话容器各层的最小高度，并保留占位的边距，减少截图脱离文档流导致的虚拟列表高度收缩。
- 保留原 DOM、原宽度、四周留白、单张原生长截图；不重新生成答案、不改变视口、不滚动拼片。
- 成功与失败详情记录 revision=anchor-recovery-v2、尝试次数、失败阶段，便于分辨实际加载版本。
- 现有 probe 新增可选 capture 对象（url 与 messageId 必填），对指定已有回答执行同一截图管线。诊断结果及 PNG data URL 存入 probe 报告，不向 GPT 发问题、不主动投递微信；目标不匹配仅写诊断错误。

## 验证

72 项完整自动化检查通过，含真实本机 Chrome（125% 像素密度）：初始锚点丢失、稳定等待期间重建、截图后重建、目标缺失时拒绝错截、flex 容器高度保护、当前真实属性结构和隐藏副本。原连续长图 40 个像素采样、样式恢复、图片上传、投递状态回归均通过。

已在线读取真实页面结构，尚未完成新版在用户已登录页面上的截图验收。无可控制的 Chrome 浏览器连接，Windows UI 工具此前无法可靠确定浏览器 URL，因此不盲目发送快捷键。

## 生效与验收

本次只更新扩展和测试，不需要重启 worker。需重载 GPT Relay Bridge 扩展，再刷新对应 ChatGPT 页面，后台和页面脚本都加载新版后才生效。

可用现有 relay.mjs probe --file spec.json 对已有回答做诊断。spec 的 capture.url 必须匹配当前页面地址，capture.messageId 必须是目标回答的真实稳定 ID。验收需同时确认 capture.dataUrl 有值、capture.info.revision 为 anchor-recovery-v2、完整图片能正常解码；截图是否已发送微信是另一项 delivery 状态，诊断不会伪造投递成功。
