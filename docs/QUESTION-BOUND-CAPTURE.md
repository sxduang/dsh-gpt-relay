# 截图对应本次问题的修复

2026-11-01，版本标识 `question-bound-v1`。

## 发现的问题

原来的回答检测只记录任务开始时的回答节点、消息 id 和文字前缀。在长对话虚拟列表重新挂载、历史消息延迟加载、上传图片等待期间，这种差集不等于“本次回答”。程序还会锁定第一个新消息，导致搜索中间说明和最终回复使用不同消息 id 时无法正确完成。

另一个明确的错图来源是 `no-answer` 失败分支：它会截图当前页面，worker 仍将此图发到微信。画面可能是上一个问题。实际日志存在两次 no-answer。无法仅凭日志确定用户所指的每张错图来自哪一分支。

## 现在的行为

- 上传结束、发送之前才建立基线，记录用户消息和历史 turn id（包括未渲染的占位 turn）。
- 必须出现一条新的、文字与本次提交一致的用户问题，并且在发送前最后一个问题之后，才开始识别答案。重复同一句话使用不同消息 id，仍可区分。
- 当前 ChatGPT 使用 data-user-message-bubble、data-turn-key、data-chatgpt-selection-message-id。只从本次问题所属 turn 选择答案；旧页面使用用户消息顺序限定。
- 同一 turn 的搜索中间说明不能锁死答案；等待该 turn complete 和文本稳定后，选择其最终回答。超时不把中间消息作为最终答案。
- 正在打开的已有对话如果尚未加载用户消息，停止发送并保留草稿。图片任务可按原 id 继续，不新建会话。
- 截图前核验绑定；截图准备、测量和拍摄后再次核验稳定消息 id 与文本特征。即使同一个 DOM 元素留下旧标记，也不能截图另一个消息。
- no-answer 不再发送当前屏幕作为兜底。没有可靠对应关系时明确失败。
- 成功结果 meta.answerBinding 记录 revision、questionKey、answerKey；probe 输出 answerBindingRevision 供重载后确认版本。

## 验证与部署

独立本地无头 Chrome 覆盖历史延迟加载、重复问题、搜索中间回复与最终回复、隐藏副本、同一问题重挂载、节点身份在拍摄前/后被复用、原任务图片暂停继续，以及等待失败不发送旧页面。原连续长图像素检查和完整中转回归一并运行。测试不向真实 GPT 提问，不向微信发送消息。

仅更新扩展源码和构建文件；worker 无需重启。部署后需要重载扩展并刷新 ChatGPT 页面。刷新前需确认没有尚待发送的草稿。

限制：对话网络未加载、问题锚点消失、或页面改版导致身份无法核对时会明确停止，不保证这种情况下仍能生成截图。实际发送链路验收需新版扩展加载后的一次正常提问；不能把本地测试通过当成真实微信投递成功。
