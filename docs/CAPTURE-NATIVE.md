# 精确回答定位与单次长截图

2026-11-01。项目：<repo>。

## 本次修复

原先等待回答结束时已经取得了回答节点，截图请求却仍下发通用 assistant 选择器，后台重新选“最后一条”；虚拟列表重建节点后还可能把历史回答识别为新回答。截图继续依赖逐屏滚动和拼接，长对话中的重新布局会使速度和连续性不稳定。

现在的流程：

1. 发送前记录已存在的回答节点、稳定消息 ID 和文字前缀。生成期间锁定新回答；节点重新挂载时只按相同稳定 ID 恢复，不跳到无关回答。
2. 截图前在本次回答节点上设置包含任务 ID 的唯一 data-gpt-relay-answer 标记。后台只接受该标记，找不到时明确报错，不回退到最后一条或全页。
3. 临时把原始回答元素放到可直接捕获的位置，保留原宽度，用等尺寸占位维持原对话高度。没有复制、重新排版成另一套内容，也没有重画图表。
4. 对原始回答使用 Chrome 的 Page.captureScreenshot + captureBeyondViewport，一次捕获整条回答；不滚动历史，不使用拼接切片，不改变窗口或视口尺寸。
5. 最终图片保留四周 24–48 CSS 像素留白。成功和失败均恢复原始样式、滚动位置，并移除定位标记及占位节点。
6. 移除截图前后重复滚到底部的操作，截图信息增加 mode=native-answer、slices=1 和耗时，便于排查。
7. /result 的请求体上限由约 2 MB 调整为 48 MiB，避免完整长图在回传时被旧限制截断。其他接口限制保持。

## 验证

58 项测试全部通过，包括图片上传及现有会话流程。旧滚动截图测试已被新的定位、错误恢复和真实浏览器测试替换。

真实 Chrome 测试使用独立、无登录的本机测试页面：前置约 120000 像素历史内容、固定浮层、带 transform/contain 的内层滚动容器，以及包含 40 个连续色块的 6000 像素回答。验证：

- 一次截图得到含留白的 660 × 6060 CSS 像素图片。
- 40 处像素采样全部吻合，无缺失、重复或分段。
- 在 100% 和 125% 像素密度分别通过；125% 时输出 825 × 7575 像素。
- 截图阶段约 0.3 秒（仅此测试页测量，不包括 GPT 生成时间，不承诺所有页面相同速度）。
- 成功和注入截图失败后，DOM、视口和滚动位置均恢复。
- 超过旧 2 MB 限制的截图结果完整保存。

电脑操作工具因无法可靠识别浏览器当前 URL 而停止，因此没有对正在登录的真实 ChatGPT 对话做本轮验收。以上真实浏览器验证是本机测试页，不应混同为真实 ChatGPT 已通过。

## 生效和回退

现有任务结束后，重启 worker → chrome://extensions 重载 GPT Relay Bridge → 刷新 ChatGPT 页面。

若报 answer-anchor-lost，不会改截其他消息；若报 answer-too-large-for-single-image，说明单次截图超出本实现的 30000 CSS 像素高度或 3200 万物理像素预算。此时不自动分片发送，保留原有文字和文件处理。

源码重点：extension/src/content/answer-target.mjs、wait-answer.mjs、capture.mjs；extension/src/background/native-capture.mjs；relay/results.mjs。
