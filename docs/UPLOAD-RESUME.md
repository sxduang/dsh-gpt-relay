# 图片慢加载与原任务继续修复

2026-11-01。项目 <repo>。

## 已核实问题

03d25e23、4dfc6b49 等任务约 60 秒后报 image-upload-failed，随后草稿仍留在网页。CLI 对仍处于 queued/running 的任务也输出失败，DSH 因此进行新 ask、--new 或换会话。原代码仅在成功回答后保存会话映射，且新对话任务可能同时带旧 conversationUrl；这些状态不一致会放大循环。用户/DSH 后来已把磁盘等待值延长到 240 秒，但单纯延时没有暂停和继续原草稿的协议。

## 当前行为

上传只执行一次，等待时重新寻找当前输入框，以兼容 React 重建。只检查附件区域的上传状态，并等待缩略图完成解码和发送按钮就绪。自动等待最多 240 秒，超时保留原问题/附件，将原任务置为 paused。CLI 对运行中任务明确显示仍在处理；paused 时给出 resume 原任务的指令。

resume 不新建任务、不导航、不上传，只在原标签页/URL 验证原任务草稿，检查文本与可取得的附件文件名后继续等待就绪。准备提交时向 worker 申请一次发送许可；已提交、过期或重复请求不能再次获取许可。发送后单独等待网页确认，避免把短暂网络延迟当作需要重发。

同一会话有未提交的图片任务时，worker 拒绝替代 ask/--new。页面草稿检查在新建聊天及跳转之前进行。新对话不再携带旧对话导航目标；已取得真实会话 URL 时提前保存映射。重复/过期结果不能覆盖任务状态或重复投递。

新增 CLI resume <id>（不是微信斜杠指令），HTTP /resume、/job-state；health 新增 uploadResume 能力，lastTabSeen.uploadResume 标识扩展协议。旧扩展不能领取新图片任务，CLI 也会拒绝向旧 worker 提交图片，避免混合版本误操作。微信插件未修改。

## 验证与边界

完整回归 79 项通过，包括真实本机 Chrome 模拟慢上传、输入框重建、暂停后继续：文件读取/上传/发送各一次、新建聊天零次。另覆盖任务暂停、阻止替代 ask、原标签页限定、重复恢复与发送许可拒绝、过期结果拒绝、CLI 不误报失败、截图和原图回归。

测试没有向真实 GPT 提交问题，也没有向微信投递测试消息。现有草稿不会被自动接管或重发。旧失败任务没有新协议的所有权记录，不能安全迁移为可恢复任务。

任务状态仍保存在 worker 内存，网页草稿仍由当前页面及 sessionStorage 保留。暂停后不要重启 worker 或刷新有附件的网页；重启后的旧任务会被拒绝恢复，而不是自动重新上传。这一限制已写入 DSH 操作约定。

## 生效

安装源代码与构建产物后，需要新版 worker 与扩展同时加载。确认无运行/排队任务后可重启 worker；重载 GPT Relay Bridge 后刷新 ChatGPT 页面。若当前有未发送草稿，应先处理草稿再刷新，避免附件丢失。最终以 health 的两项 uploadResume 标识核对。
